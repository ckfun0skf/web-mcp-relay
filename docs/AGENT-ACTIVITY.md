# Agent activity indicators (0.8.1)

Relay connectivity and agent use are separate. New sessions show Waiting for agent even when their browser socket is connected. A routed relay request with a valid request ID and list/call operation marks first/last agent activity for that specific session. Copying a key, opening help, local discovery, a WebSocket ready frame, keepalive, or generic connector tool discovery does not mark agent activity.

The popup and session manager show Relay status separately from Agent status. The copy panel acknowledges recent detected activity. Agent states include Waiting for agent, Processing agent request, Awaiting your approval, recent activity detected and Last active. Processing includes discovery/validation/approval handling and is deliberately NOT labelled Running tool. Recent activity is not authenticated identity or a guarantee of a currently connected agent. Busy, rejected or denied requests still prove a caller reached the session, not that its operation succeeded. Counts are received requests, not unique executed tool calls.

No inactivity expiry, disconnect inference, heartbeat requirement or permission bypass is introduced. Agent telemetry wraps the existing multi-session engine without changing request authorization or execution. Relative age labels update without rebuilding unchanged session rows. Names and session IDs continue to distinguish agents operationally; possession of a shared key cannot identify which caller used it.

Only first/last receipt timestamps and a count are stored in TRUSTED_CONTEXTS chrome.storage.session under relayAgentActivityV1, keyed by live session ID. No keys, arguments or results are stored in this telemetry record. History may survive worker restart while session storage remains, but active processing is never restored. End removes that session's history. No pre-upgrade activity is fabricated and old history can therefore start as Waiting for agent. Reconnect retains history, displayed as historical last activity rather than proof of a new attachment.

Six pure activity/formatting tests passed locally using node --test extension/agent-activity.test.mjs. They cover no false detection from relay readiness, session isolation, processing/approval versus disconnected history, idle history without expiry, history-only restoration and invalid/ended records. Adapter, browser rendering and real agent/Cloudflare end-to-end tests remain unverified. No automatic CI workflow or relay source change is included. Update local files and reload extension 0.8.1; no Worker redeployment is needed for this feature when the compatible no-expiry relay is already deployed.
