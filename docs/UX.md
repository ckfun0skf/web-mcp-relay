# Onboarding and safe docking (0.2.0)

The existing app.js transport/native execution engine is unchanged. app.html is now a five-step Traditional Chinese setup wizard: deploy, secret, health verification, WebSocket connection, ChatGPT handoff. Back/Next does not reload the engine. Cloudflare deploy opens a separate popup; its close event never implies success. A manual existing-relay route is available. Actual Cloudflare wizard labels and deployment success still require live testing.

Optional host permission is requested ONLY for the relay origin selected by the user, to run the health check. WebMCP page access remains activeTab + scripting. Broad optional permission declaration is not an automatic all-sites grant. Only non-secret relay URL, setup progress and layout preference are stored. No credentials go into deploy URLs. Existing transport clears OWNER_SECRET after connecting; reconnecting requires re-entry.

Four display controls: left/right/bottom mount a minimal extension-origin iframe in a closed shadow root on the explicitly selected webpage, reserving space using root padding; separate-window removes it and restores the previous inline styles. This is NOT Chrome DevTools or native Side Panel docking. Fixed-position site elements and unusual layouts may overlap; root style changes/restoration are best effort. Chrome internal/restricted pages cannot be docked. The dock preference is recorded but not auto-applied on startup; users explicitly choose placement.

Security boundary: only dock.html, dock.js and style.css are web-accessible. app.html/setup.js/app.js are NOT exposed. A dock can show sanitized connection status, setup progress and target text, reposition itself, or focus the control window. It never receives OWNER_SECRET, session_key or approval arguments. All setup and tool approval remain in the extension-owned popup, because a hostile embedding site can obscure/clickjack an iframe. A pending approval restores/focuses that trusted window.

Docking minimizes (does not close) the existing controller, so session keys/approval state stay in its memory and mode switching does not intentionally reconnect. Keep that window open. Browser restart, extension reload or forcibly closing/discarding it still disconnects. Background session directory is ephemeral and refreshed by the controller; a service-worker restart can briefly show unavailable. Closing the controller attempts to remove its dock. Website navigation removes the injected panel; old native document bindings remain invalid as before.

Acceptance tests NOT yet browser-verified: initial/repeated setup; Next guards; Back preserves input; generated secret not persisted; Cloudflare popup and manual fallback guide; compatible/incompatible/timeout health; optional permission denial; connect/reconnect; both native API errors; docking on left/right/bottom without changing session key; separate-window restoration; reconnect after service-worker idle; controller close cleanup; page navigation; denied and approved calls from docked mode; approval window restoration; keyboard focus, narrow viewport and reduced motion. No relay code or old PoC files changed.
