# Live multi-session integration (0.8.0)

This update switches the manifest to multi-background.js and the toolbar to workspace.js. Legacy singleton background/policy modules and the Demo preview remain in the repository but are not imported by the active entry point. A maximum of 32 saved sessions is enforced. Each runtime owns its socket, key, heartbeat, generation, document binding, trust scope, grants, pending approval and busy flag. No time-based expiry.

The popup shows up to three sessions on the current tab, prioritizing pending approvals, plus a total approval count across pages and Manage sessions. sessions.html uses live background summaries, grouped by origin and tab, with search/filter, independent copy/pause/reconnect/rename/end, and confirmed end-all for the captured IDs. Additional sessions never replace an existing connection. Labels are not authenticated agent identities. New sessions use the currently selected relay; existing sessions retain their original relay. Reset explicitly ends all sessions before removing relay credentials; website trust remains separately managed in Options.

Private trust dialogs include both session ID and document policy scope. Choosing a mode navigates the same dialog to the key-copy panel. Approval buttons send session ID and request ID. Revoking a saved website invalidates every matching runtime, not just the focused tab. Refresh keeps keys but resets ephemeral grants; users can reopen Permissions for any session. Metadata listing is read-only.

Same-page tool execution uses the tested TabExecutor. Approval waiting does not hold the page lock. Competing dispatch receives PAGE_BUSY, not an automatic retry; different tabs are independent. Locks remain held until native execution settles, even after caller disconnect/timeout. Already-started effects cannot be cancelled or rolled back by Pause/End.

Session metadata/keys are serialized to TRUSTED_CONTEXTS chrome.storage.session. A remaining old relaySession record is migrated before removal. Restored runtimes start disconnected without ephemeral trust; reconnect is explicit. Browser restart/extension reload may clear session storage. Only extension-owned pages can request handoff keys or management state; content hints receive metadata/reduced status only. Website trust and relay credentials remain separate.

The existing relay already routes distinct session-key hashes to separate Durable Objects, so this update makes no relay source changes. It requires the previously deployed no-expiry relay reporting sessionExpiry: manual; older Workers are rejected.

Verification: JavaScript syntax checked with Node. Ten local Node tests with mocked sockets/storage/native execution passed: independent same-page runtimes and keys, isolated approval/trust/pause, restore without automatic trust, wrong-session approval rejection, multi-runtime website revocation, approval waiting without page-lock starvation, same-page overlapping dispatch rejection, pause rejecting a pending request, reconnect retaining a key, and selective cross-origin termination. This is NOT real Chrome/WebSocket/Cloudflare validation. No new CI workflow is added. Browser permissions, clipboard fallback, page visibility and popup/dialog behaviour remain manual acceptance work.
